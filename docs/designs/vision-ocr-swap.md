## Vision

### 10x Check
The bot's read layer becomes invisible: per-crop reads land in 15-30ms and
full-frame sweeps in 90-380ms on the Neural Engine, versus 60ms-2.7s on 4 CPU
threads under PaddleOCR. tap_on_text polling loops that today burn a full 2s
window converge in 2-3 ticks. First-install boot loses the multi-minute Paddle
model download (run.sh polls readiness up to 120x2s = 240s to cover it). The
Mac stays responsive while the bot runs.

Evidence, with the numbers labeled ("Vision accurate" = VNRecognizeTextRequest
at the .accurate recognition level; all bake-off Vision numbers were measured
in-process through the PyObjC bridge, the same mechanism the swap will use):
- Bake-off, 31 padded ROI crops + 4 full frames at 1080x2460: Vision accurate
  found 37/37 expected full-frame strings vs Paddle 36/37. Raw crop scores:
  Paddle 29/31, Vision 28/31. Two crops had a defective recorded box (the
  ChiefProfile.Stamina box clips today's wider value) that truncated the INPUT
  for both engines identically; excluding those two shared-input defects, the
  chief-profile set scored Paddle 17/17 vs Vision 16/17 (the single miss is the
  stylized badge digit "3" — the case the fallback exists for).
- Crop latency: Paddle median 63-64ms; Vision accurate median 17-18ms.
  Full-frame: Paddle 961-2771ms; Vision accurate 86-376ms.
- Independent Swift harness on a live 2160x3840 frame (~3.1x the pixels of the
  1080x2460 base): 28 lines in 0.26s, all confidences 1.00.

## Approach (what "B" means)

Three approaches were considered. A = minimal swap (no flag, no fallback,
completeness 6/10) — rejected: no rollback path and badge-digit reads break.
C = ideal architecture (B plus dead-code deletion and native high-res capture,
completeness 10/10) — not taken whole; its items were cherry-picked below.
**B = guarded swap (chosen, completeness 9/10):**

- New Vision engine module behind the existing `run_ocr()` seam in core/ocr.py;
  the HTTP contract `[{text, score, box}]` in 1080x2460 pixel space is unchanged.
- Bridge mechanism: PyObjC (`pyobjc-framework-Vision`), in-process in the
  existing FastAPI server. Every Vision call runs inside an explicit
  autorelease pool (`objc.autorelease_pool`) so repeated CoreGraphics/Vision
  calls from the persistent server cannot accumulate Objective-C objects; the
  burn-in log line includes process RSS so the burn-in doubles as the leak check.
- Engine default matrix: `OCR_ENGINE` unset -> vision on macOS >= 13 (Ventura),
  paddle everywhere else (older macOS, Linux). `OCR_ENGINE=vision` explicitly
  set on an unsupported platform fails loudly at boot.
- Seam contract includes coordinate-convention normalization: Vision returns
  normalized bottom-left-origin boxes; the engine converts to pixel
  top-left-origin boxes identical to Paddle's output. A pytest case asserts
  box agreement within tolerance on ground-truth frames.
- Fallback policy (amended 2026-08-30 after first live run): Paddle is
  invoked lazily ONLY when Vision returns zero items on a read_kind=value
  crop (the detector-refusal case, e.g. isolated badge digits). expected_text
  alone does NOT trigger fallback — run 0 showed 23/38 reads were label POLLS
  for text legitimately absent from screen, where fallback doubled every poll
  tick, loaded Paddle for nothing, and polluted the fallback metric. Vision engine EXCEPTIONS
  (bridge errors, framework failures, malformed images) are logged and treated
  as zero-item results, subject to the same fallback rule; three consecutive
  exceptions flip the session to paddle with a loud log line. Non-empty
  misreads do NOT fall back — they are absorbed by the existing rapidfuzz>=80
  matching, retry loops, and evidence-gated state changes, and Vision's
  measured misread rate is at or below Paddle's (37/37 vs 36/37).
  Expectation-free reads (full-frame sweeps) never fall back. Paddle models
  are already cached at ~/.paddleocr/whl; measured lazy-init with cache is
  ~0.3s, not a download. Fresh machines: one-time prefetch documented in setup.
- Confidence filter: the server-side per-line `score > 0.8` filter
  (core/ocr.py:737) is kept. Cross-engine validity was measured, not assumed:
  Vision accurate scored 1/90 results below 0.8 (median 1.00) in the bake-off.
- Merge gate (decided in deep review, D-2B): a deterministic fixed-frame
  suite — the 4 bake-off fixture frames (~60-80 ground-truth entries) with
  Vision's fuzzy>=80 rate >= Paddle's on the same frames — plus the existing
  ~90s single-account live smoke. Coverage grows during burn-in as screens
  are visited naturally; the full 355-entry screen-walk suite is explicitly
  NOT the merge gate (brittle, game-state dependent).
- Burn-in observability: every read logs engine, per-call latency, fallback
  hits, process RSS, and — for digit-bearing expected reads — expected vs got
  digits with a greppable `DIGIT_MISMATCH` tag. Burn-in exit: 7 days of normal
  runs or >=2,000 expectation-carrying reads (the denominator for fallback
  rate), with fallback rate <1%, zero unwaived DIGIT_MISMATCH incidents, and RSS
  growth under 200MB across the window with no monotonic upward trend
  (failing the RSS criterion reinstates the RAM-cap machinery on the vision
  path and reruns the burn-in).
  A DIGIT_MISMATCH that does NOT reach an evidence gate is root-caused: if
  attributable to a transient frame and absorbed by retries/fuzzy matching,
  it is recorded and waived (does not block exit); otherwise it is treated
  as the gate-reaching case. Failure actions: any DIGIT_MISMATCH that
  reaches an evidence gate ->
  immediate rollback to `OCR_ENGINE=paddle`, capture the frame, reopen this
  review; fallback rate >=1% at week's end -> reopen scope item 3
  (template-digit fallback) with the data, burn-in continues under vision.
  Exit with all criteria met reopens the Paddle-removal decision.
- run.sh: readiness poll stays; it mirrors the engine default matrix, so the
  120x2s cap drops to 30x2s whenever the RESOLVED engine is vision (not only
  when OCR_ENGINE=vision is explicitly set).

### Outside-voice decisions (cross-model review, all accepted)
- 3A: value-read call sites tag read_kind=value; zero-item value reads fall
  back to Paddle; during burn-in every value read is shadow-read by Paddle and
  DIGIT_MISMATCH = engines disagree on digits. Burn-in denominator = decisions
  (not retried reads); exit needs 7 days AND >=2,000 decisions.
- 4A: paddle imports + GC env flags move into a lazy factory; vision-default
  boots never import paddle (makes the boot/RSS claims true).
- 5A: run.sh untouched — the 120x2s cap is a ceiling vision boots never hit.
- Folded fixes: breaker flip never downloads models mid-session (models absent
  -> stay vision, loud log); merge-gate fixtures = in-repo frames only, no
  personal-ID frames; CEO-doc merge-gate contradiction corrected.

### Deep-review decisions
- D-1A: the global OCR lock stays in v1 (Vision reads remain serialized);
  dropping it for the thread-safe vision path is a one-line follow-up after
  burn-in. Rationale: right-sized diff, clean bisection.
- D-2B: merge gate is the deterministic fixed-frame suite + live smoke (above).

### 2x render probe — explicit adopt/reject criteria
Runs only after burn-in exit. The run.sh framebuffer gate parameterization
(`WOS_FRAMEBUFFER`, default 1080x2460) ships WITH the probe, not with the
swap; the default stays strict. "The 0.5x normalize" = the existing
`_normalize_frame_resolution` step in core/ocr.py that resizes every captured
frame to the 1080x2460 base before OCR and template matching; at 2160x4920
that resize is a uniform 0.5x on both axes. Adopt only if ALL hold: (a) MuMu
accepts 2160x4920 @ 840dpi and `wm size` reports it cleanly; (b) all 61 icon
templates still match at threshold >=0.8 via tap_on_templates_batch smoke on
the Home and World screens after the 0.5x normalize; (c) the 355-entry
ground-truth ROI suite's fuzzy>=80 rate does not regress vs the 1080x2460
baseline; (d) the badge-digit crop cases that miss under Vision at 1x (e.g. the
furnace badge "3") read correctly at 2x via the crop suite. Any failure -> reject, restore
default, record findings.
